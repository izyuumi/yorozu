# Action Execution

## 1. Capture

Create or update an execution item with objective, success criteria, dependencies, urgency, risk, and project links.

## 2. Retrieve

Load relevant current state, past actions, preferences, explicit boundaries, authorization rules, SOPs, and capability limitations.

## 3. Classify authority

- current explicit request that includes commitment;
- active learned authorization matching all material dimensions;
- preparation-only authority;
- no authority.

Priority and SOP applicability do not grant authority.

## 4. Prepare

Perform reversible research, comparison, drafting, form filling, or staging. Minimize sensitive disclosure. Identify the exact commit point.

## 5. Pre-commit check

Verify:

- target and recipient;
- quantity, dates, variant, and scope;
- total cost and recurring terms;
- account and payment method class;
- privacy and legal significance;
- cancellation or recovery path;
- authorization rule and match rationale;
- whether the external state changed since preparation.

If a material dimension is ambiguous or outside authority, request confirmation with the decision-ready facts.

## 6. Commit

Perform the single intended side effect. Avoid duplicate submission. Capture confirmation metadata without secrets.

## 7. Verify

Use reliable external evidence. If uncertain, mark `verification-required` and inspect external state before retrying.

## 8. Reconcile

Update action log, queue, project, world state, purchases/deliveries if applicable, authorization evidence, and session journal.

## 9. Learn

Record corrections, satisfaction, failures, unusual friction, and reusable SOP improvements. A successful action can strengthen a rule; a negative outcome can narrow or suspend it.
