Yorozu v1 Spec

Out-of-box personal AI assistant for macOS, remote-controlled from iOS through a blind E2E relay. Result of a 30-question grill session between Yumi and Molty, 2026-09-12.

Differentiator: install, grant every macOS permission once, scan one QR, start talking. Everything else already exists somewhere; the install path and the approval engine do not.

Not OpenClaw: clean-room harness. One loop, agents as markdown files, full permissions by default, AI-gated approvals that learn, phone-native session list.

2. Providers

  • Onboarding shows three cards: Claude, Codex, OpenAI-compatible. Any one green unlocks the app.
  • Claude and Codex: detect installed CLI on PATH and logged-in state. Missing login runs claude login / codex login in embedded terminal. Nothing bundled, no redistribution.
  • OpenAI-compatible: base URL + key. Model IDs via /models, price unknown unless catalog overlay provides it.
  • Runtime owns the loop. Each provider is a thin adapter: stream(messages, tools) and auth(). Claude Agent SDK and Codex SDK used only for auth and streaming. No harness registry, no per-model runtime switching.
  • Routing: settings hold primary model and fallback chain. Auth or rate-limit failure moves to next in chain. Agent file frontmatter may set model:.
  • Auto-assign button: default model reads every agent .md plus catalog, writes model: into each frontmatter. Shown as diff, revertible. Can run on cron (daily, weekly, monthly). Two knowledge sources, user picks: GitHub catalog, or research mode where the model web-searches current pricing and writes a local catalog overlay.

3. Agents

  • Agent = agents/<name>.md. Frontmatter is opt-in restriction only: model, tools allowlist, memory scope. Absent field = inherit main agent's full tools and full memory.
  • Main agent talks to user. One tool delegate(agent, task, background?). Depth 2 hard limit; specialists cannot delegate. A specialist needing another specialist returns a structured "needs X" and main re-delegates.
  • Sync by default. background: true returns immediately; completion arrives as an event in the same thread. User interrupt cancels the whole tree.
  • Every agent emits per-step events (thought, tool call, tool result, final) tagged with agent ID and parent ID. Drives the phone drill-down.
  • Skills: AgentSkills format, skills/<name>/SKILL.md. Existing skills drop in unchanged. Loaded on demand by name.

5. Memory

  • memory/ directory of plain markdown. Files are truth. User-editable, Obsidian-openable, git-able.
  • SQLite with FTS5 + sqlite-vec is a derived index, rebuildable from files. Local embedding model; provider embeddings when a key exists.
  • Writes: explicit remember during conversation, plus nightly consolidation job (via scheduler) that reads the day's transcripts, extracts missed facts, dedupes, promotes. Every fact carries date and thread provenance.
  • Approval decisions are a memory kind of their own. See section 6.
  • Single user. Shared memory across all threads and devices.

6. Approval engine

Technically unrestricted. AI decides whether to ask. Code enforces the floor and the learned rules.

  • Every external action carries class (send-message, purchase, delete-file, book, transfer-money, run-command, edit-file, ...), target, optional amount.
  • Floor, set at onboarding, two settings: money threshold per action; whether irreversible deletes outside app directories need confirmation. Code-enforced, cannot be overridden by "never ask again."
  • Decision log: append-only rows (class, target pattern, decision, timestamp). Checked in code before any prompt.
  • No precedent → ask once. Consistent precedent → act, mention in passing. Mixed → ask.
  • Yes, and never ask again allows the action and writes a permanent rule row. Matches by class unless the user names a target. "Always send emails, never ask again" covers all recipients. Guaranteed: the action runs and the user is not asked again.
  • Phone card: Yes / Yes, and never ask again / No / Discuss. No refuses this one action only. Discuss keeps the action pending; agent explains reasoning and options in chat, then re-presents the card. Typed replies also accepted.

7. Sessions and phone UX

  • Thread list. Tap + to create; optional name. Pinned "Home" thread never archives.
  • Thread view is a plain chat between user and main agent, Signal/WhatsApp shape.
  • When a specialist is running, an inline card appears. Tap opens the specialist's live trace: thoughts, tool calls, output.
  • Phone keeps an encrypted local cache. On connect it sends last-seen event ID per thread; Mac streams the delta. Readable offline.
  • Mac app shows the same SwiftUI chat locally, no relay hop.

8. Relay and pairing

  • Mac generates a keypair at install. Room ID = hash of public key. Mac registers with a signed challenge.
  • QR carries Mac public key + one-time join token. Phone joins; relay verifies signature, drops unsigned frames, rate-limits per room.
  • Phone and Mac do key exchange; relay forwards ciphertext only. No accounts, no email, no readable state.
  • Mac offline: relay buffers ciphertext per room, 24h TTL, size-capped. Phone shows "delivered to relay, Mac offline."
  • Onboarding sets Mac to never sleep with consent.
  • Any number of phones/iPads pair to one Mac. Single user.
  • No APNs in v1; phone must be foreground to receive.

9. Distribution

  • Mac: Developer ID signed, notarized DMG, Sparkle auto-update, GitHub Releases. Node sidecar and Chromium download on first run.
  • iOS: TestFlight day one, App Store once stable.
  • Relay: Docker image, one command. Yumi hosts a default instance.

10. Onboarding flow

  1. Open DMG, drag to Applications, launch.
  2. TCC wizard: Accessibility, Screen Recording, Full Disk Access, Automation, Input Monitoring. Each step verifies grant, retries.
  3. Provider cards. At least one green.
  4. Two floor settings.
  5. Browser picker.
  6. Never-sleep consent.
  7. QR shown. Scan from iOS app. Done.

12. Risks

  • Scope: three codebases plus runtime. Roughly three months solo to reach daily-driver parity with current OpenClaw use.
  • Subscription CLI auth terms may change. OpenAI-compat path is the safe floor.
  • AX coverage gaps in Electron apps push more work to screenshot fallback.
  • Always-rule matching too narrow re-prompts and breaks the "never ask again" promise; too broad over-authorizes. Class-level default with optional target is the chosen balance.
