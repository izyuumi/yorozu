# Lifecycle refresh and cancellation fences

The host `stopAccount(binding,reason?)` callback now distinguishes `refresh`, `replace`, `sign-out`, `select`, `close` and `invalid`. Existing callbacks taking one argument remain type-compatible, but production composition must handle the reason: **routine refresh must not close the broker or abort its current token-request signal**. The lifecycle holds account admission privately while rotating/verifying credentials. `canExecute(binding)` reads only validated cached lifecycle state and synchronous store availability, without protected reads or initialization. The broker's current-authority closure must check it. Successful same-identity/same-scope rotation unfences the account; unknown/invalid or changed scopes hold it and invoke `invalid` to retire all old brokers. Replacements, sign-out, selection changes and close retire affected old executions.

`cancelSignIn(attemptId)` now tracks the exact consumed in-flight attempt, synchronously fences its binding and aborts its exchange/verification controller. Pre-callback cancellation only removes that in-memory attempt. Cancellation cannot target another attempt by guessing the latest account. Late exchange/verifier results cannot produce a successful adoption receipt. A cancellation racing an already-dispatched durable commit remains unknown and fenced; it does not promise to roll back a commit. Unknown exchanges are never replayed; returned pending credentials remain protected/quarantined. Cancellation is not proof of remote OAuth cessation or revocation.

`validateSiwcProtectedSnapshot(value,expectedHost?)` exposes the existing pure snapshot schema check for the native store bridge. It performs no reads, account probes or storage writes. Native helpers must enforce the same bounded record/phase schema and preserve immutable host/registration identity during revision-CAS replacement.

Inert tests compose refresh with a broker-style abort controller, prove successful rotation leaves its signal live, prove unknown/narrowed rotation retires it, and cancel exact exchanges/verification while callbacks ignore abort. No credential access, native helper, socket, browser, Keychain or inference runs.
