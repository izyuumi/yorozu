# Architecture / R1 boundaries

## Stack and local boundary
Python standard library HTTP server + SQLite + vanilla HTML/CSS/JS. Loopback bind, exact Host/Origin guards, JSON/custom-header write requirement, no CORS, CSP, textContent rendering. One app process per data directory. This is not protection against other local processes and not a public-hosting stack.

## Main flow
HTTP preserves original user input and returns immediately. Two independent secretary lanes build <=3 recent excerpts, <=8 topic candidates and <=8 compact active-task references. Structured model output selects quick reply, substantive delegation, strict existing-task steering or ambiguity clarification. Substantive analysis is delegated automatically; ambiguous target selection gets one configurable stronger-model review, then a concise question. No dispatch/steer occurs while unresolved.

Delegation persists a stable task and bounded context; two worker lanes execute independently. UI polls every 1.5 seconds and posts completed worker text immediately with originating-request attribution. Results may arrive out of order. Neither late worker output nor its topic changes the user's active discussion topic. Details is read-only; no secondary composer. A capability-specific observer polls only the exact project worker session via chat.history every two seconds (last 40 committed messages). It persists ordered/deduplicated visible assistant messages and tool names with source IDs; no live token snapshots, reasoning, tool arguments/results or invented progress. Potential credential-shaped visible text is withheld conservatively. Main timeline gets a brief receipt acknowledgment plus final answer, not intermediate events. This is committed-message delivery, not a claim of complete ephemeral WebSocket progress capture.

## Harness boundary
`GatewayModelAdapter` uses the supported configured Gateway CLI with `agent(modelRun=true,promptMode=none)` for stateless secretary/extractor/escalation calls. Existing authentication remains owned by OpenClaw. The loopback destination is asserted using `--expect-url`; no credential extraction/copying.

`GatewayWorkerAdapter` creates fresh project-only worker/controller sessions, then sends an initial lightweight-bootstrap/minimal-prompt `agent` request into the worker. Native worker permission remains read-only; the output contract forbids unrelated native tools/files/private sessions/delivery. The app separately binds an explicitly authorized scoped memory-file capability. Worker-selected memory_call requests execute immediately and real results continue in the same existing Gateway session, without creating a new task/session. This is an application-mediated protocol, not native Tool Search registration. R1 is knowledge text, not coding/browser execution. Exact app wire context is stored with its handle. This is not a claim that all harness-added framing is included in the inspector.

Steering uses `tools.invoke`/`sessions_send(mode=steer)`, never an idle-start chat.send fallback. Exposure and actual live behavior still require the owner-terminal probe. No global policy changes are made. Receipts and model-reported incorporation are separate: accepted_not_confirmed -> applied_confirmed_by_output only when the latest admitted revision appears in terminal worker output. Stale outputs remain inspectable. Transactions reconcile completion-before-receipt races and prevent duplicate answers. Failure retains the same task/amendment and never silently replaces it.

The legacy isolated `agent exec` adapter remains selectable for diagnostics but cannot steer. Offline mode never pretends a test double is a live model. See GATEWAY_REVIEW.md for actual native-model success and the still-unverified standalone app transport.

## Context bounds
Stateless app payloads <=12,000 UTF-8 bytes. Worker initial context reserves wrapper room (10,000-byte assembly with the memory contract, <=12,000-byte wire). Scoped memory-tool replies are separately capped at 26 KB, up to six operations per invocation. Selectively retrieved global memory <=2,500 bytes; recent same-topic conversation originals fill remaining budget. Topic IDs only rank/tie-break memory relevance and preserve provenance, never silo memory. Title/summary lexical discovery precedes actual Markdown reads. No growing global history replay, destructive truncation or lossy summaries. Each task/sub-chat keeps its same growing Gateway model session, including amendments, per owner decision at 16:45. No custom compaction, reset, periodic reconstruction or task-history cap is implemented; harness defaults apply. The 12 KB bound is per app-supplied input, not total retained model-session history.

## Operational ownership
Operational SQLite holds unchanged originals, topics, immutable turn snapshots, secretary/escalation decisions, stable tasks, amendments, receipts and result revisions. Each background job opens its own connection. Worker memory tools use an in-memory coordinator connection with the operational DB attached read-only and only the derived memory index writable. A result is emitted once, with source attribution. Interrupted work is marked errored on restart and never auto-replayed. Actual remote Gateway runs may outlive an abrupt app exit; do not restart/replay them as if cancelled.

## Portable memory
Hierarchical Markdown is the single source of truth. Separate memory-index.sqlite stores summaries/paths for discovery; retrieval validates paths and reads actual Markdown. Rebuild parses all source files before transactionally replacing derived rows. No watcher. Symlink/oversize/malformed source fails closed. Memory can be written with no topic provenance and rebuilt even when an old topic record no longer exists; the memory index remains separate from operational topic state.

A separate memory executor runs a pluggable semantic model extractor on user discussion/pasted text and newly committed visible assistant/worker replies. Useful personal facts/preferences/decisions, quoted source claims, generated analysis, topic synthesis and tentative hypotheses may be retained. Closed-schema output explicitly carries knowledge_type, attribution and epistemic_status. Assistant-origin knowledge cannot become a user belief; quoted material and known reported-speech markers cannot become personal user statements. No model-produced note may claim verified status. Useful hypotheses are retained as tentative rather than discarded or promoted. Source IDs/roles/kinds and exact quotes are preserved; long assistant outputs use explicitly marked bounded excerpts without modifying originals. Cross-type/attribution replacement is prohibited; nonpersonal corrections require an explicit correction marker and same-class target. Contrasting claims do not implicitly overwrite one another. Classification still depends on model judgment for unmarked or ambiguous sources; this is not formal entailment proof or exhaustive secret detection. Offline mode remains literal-only. Model quality has not been evaluated live for this change.

Corrections reuse one memory ID and preserve source/timestamp/value lineage. A metadata-only alignment pass follows resolved routing without re-extracting deleted content. Memory-job receipts prevent replay of already-processed history. Forget deletes exactly the selected fact's Markdown file and rebuilds the derived index; originals/tasks are not rewritten, redacted or deleted. No tombstones or background history deletion. Worker-directed Markdown edits are now supported with full-file SHA-256 preconditions, no-follow directory-descriptor access, same-directory atomic replacement and a small cooperative POSIX lock shared with app writers. Delayed extractor proposals also check their observed file hash. Prior identity/attribution/correction lineage is protected; worker body changes are not rewritten by a secretary. Direct owner Markdown edits remain authoritative but are not automatically versioned or forced to honor advisory locks.
