# 0034. Test conventions, harnesses and cross-language fixtures

- Status: Accepted
- Date: 2026-11-21 (recorded from code comments)

## Context

Swift, TypeScript and Rust implement the same wire, cards and Live Activity state. Tests must pin each side against the others with shared fixtures, run without OpenClaw or a real Gateway, and never touch the owner's real data.

## Decision

- Cross-language fixtures:
  - Card events: one copy, in the plugin's tree (`test/fixtures/genui-wire.json`), pinned by `presentations.test.ts`. It holds what a capable session, an old app's session and a history request get for one card reply, as the JSON inside the sealed box, for the apps' decoder tests to replay.
  - Push preview: the fixture box is sealed by the plugin's test helper `sealWithNonce` (the production cipher, key and output shape with a chosen nonce) and opened by Swift `PushPreview.open` in `PushPreviewTests`.
  - Regenerate either fixture with `UPDATE_FIXTURES=1` only when the format changes on purpose.
  - The unversioned-wire vector is generated by Swift `ClientHandshake`; `UnversionedWireTests` finishes the same response.
  - The Windows core's golden boxes were produced by the plugin's NoiseIK/Session from the same vector inputs.
  - The Live Activity content-state fixture is built at 2027-01-15T08:00:00Z, the instant the Swift test reads back; the relay's protocol test uses the same state the app decodes as `YorozuActivityState`.
  - The cron text tests mirror `CronScheduleTests` ([0022](0022-cron-schedule-text.md)).
- Plugin tests without OpenClaw:
  - The plugin's files import siblings as `./x.js`, which the Gateway's loader maps to `./x.ts`; tests register a resolve hook that does the same. Another helper's hook may already have turned the specifier into a file URL. The relay's sources do the same for tsc, and the Windows conformance host reuses the hook.
  - `genui-hooks.ts` is imported first: it sends every `openclaw/…` import, and the plugin files bound to a running Gateway, to `genui-host.js`. It holds no tests.
  - `genui-host.js` stands in for OpenClaw so the real `conversation.ts`, `history.ts`, `sessions.ts` and `presentations.ts` run. The agent run starts (`onAgentRunStart`) before `host.run`, or, with `host.queued`, when `host.run` calls `start`.
  - `presentations.test.ts` runs cards end to end this way: the plugin's own `deliver`, reply events, history pages, card store and conversation delete run as shipped.
  - Push preview tests redirect the OpenClaw runtime import in `push.ts`, used only for the title store, which they don't call.
  - `receiver.ts` runs the plugin's upload receiver over stdio for `ResumeBenchTests`: one JSON event per line in, answers out; stored files go to `<spoolDir>/../stored/<attachmentId>`. Without an argument (as `node --test` loads it) it does nothing.
  - The relay's `direct.test.ts` mirrors `openclaw/plugin-sdk/runtime-store`'s instance-scoped slot and leaves the global fallback unset. Plugin registration precedes `startAccount` in the same instance scope.
- Plugin integration tests:
  - The environment is set before every SDK or plugin import, including SDK modules with import-time state paths.
  - Every network discovery entry point is stubbed: only the fake relay may listen, on loopback. The fake relay mirrors the worker's Live Activity slot rules.
  - Durable Live Activity tests use only synthetic records, and every send checks its persistence receipt; receipts are captured at arrival, before a later save could make the assertion pass. Owner maps are injected observations, never app-report reducers. Seeded fixtures represent live host messages, so watch-only restarts keep their owner.
  - `testFileLock` is only a test double: stale-owner recovery is exercised with the SDK in integration tests.
  - The conversation-owner test replaces only relay routing, so real `handleMessage` events feed the real `ActivityWatch`. `gone` removes the only entry; a duplicate registration would leak.
  - Time: keep real time and allow 5 s for a reconnect; advance the injected wall clock near the 15 s boundary while the real hold timer still fires; urgent pushes skip the 15 s throttle.
- Relay tests:
  - The compatibility tests replay storage across the shipped and current relay: the shipped relay proves rollback by reading newer storage, and the current one replays every producer. Persistent storage is captured before cleanup, since socket attachments do not survive deploys.
  - Vite supplies the `import.meta` transform; Vite is not a direct relay dependency.
  - Client-initiated closes do not emit a client close event in the test pool, so tests wait for the relay to observe departures. Push delivery runs in `waitUntil`, after the WebSocket message settled.
  - Shallow CI checkouts need only the vendored source and manifest.
  - `vitest.config.ts` runs the node project with `oxc: { tsconfig: false }`, because `direct.test.ts` imports the plugin's pure files, whose tsconfig extends an OpenClaw checkout CI does not have.
- Swift tests:
  - The unit tests (`YorozuTests`) cover snapshots, the Live Activity, client lifecycle and voice sessions on the Mac without hosting the app.
  - Harnesses fail before `AppModel` can reach an app-owned support directory or the App Group, or choose the live path. Preview playback is off in tests, so the `PreviewScene` stub keeps `AppModel`'s real lifecycle path. Defaults go to a volatile suite, never `~/Library`.
  - The listen task applies updates on its own turns of the main actor, so tests wait for them to settle.
  - `VoiceSessionTests` dictate against the preview's clip and transcript: no microphone, no model, a transcript 600 ms after ✓. They are serialized, nested suites included, since the transcript is global.
  - Test relays keep mutable state and Network callbacks on one serial queue (snapshots cross by continuation), or connections and WebSocket operations on a queue and recorded data under a lock.
- Windows conformance harness:
  - The probe reads blocking stdin off the runtime; EOF shuts the driver down.
  - The fake host preserves receive order across async Hub calls; tests await `exited` when a controlled exit is part of the scenario.
  - A pong after an announce proves the relay handled it. Open fires on the host's `peer_info`; the Hub broadcasts only after handling the client's, which the `conv_list` answer proves. A following valid send fences a rejected command at the host boundary.

## Consequences

- A format change on one side fails the other side's tests until both agree.
