# Status

Current state of `main`. Version: `version.txt`. Product decisions: [OWNER_DECISIONS.md](../OWNER_DECISIONS.md). Release flow: [release.md](release.md).

## Implemented

- **Plugin** (`plugins/openclaw-yorozu`): host keys in the OpenClaw credentials store; relay connection with reconnect; Noise IK handshakes from allowlisted devices; `openclaw yorozu pair`, `devices`, `devices remove`. Text in and out through one OpenClaw thread session per conversation, with `run_started`, typing, `tool` rows and chunked whole replies; cron delivery into a conversation; history from the Gateway transcripts (`conv_list`, `history`); titles, rename, archive, delete; read cursors; attachments both ways (default limit 8 MB, `channels.yorozu.mediaMaxMb`); replies both ways (reply targets into the turn, `[[reply_to…]]` out); reactions both ways (system events in, the message tool's `react` out); one sealed push per finished reply; read-only cron list; device list and settings; `pair_invite` for adding a Mac.
- **Wire** (`packages/YorozuWire`, plugin `src/wire.ts`/`src/envelope.ts`): [contract](ios-relay-contract.md); the plugin accepts both frame formats.
- **Relay** (`apps/relay`): Cloudflare Worker, one Durable Object per room, one-time pairing mailboxes, APNs sender, connect rate limit; deploys on merge after its tests.
- **Client** (`apps/ios`, one target for iPhone, iPad and native SwiftUI Mac): pairing by QR scan or pasted link with fingerprint check; a new Mac shows a code that a paired iPhone or iPad scans; conversation list, chat, outbox and cache; replies (Reply in the action row and context menu, quote headers that scroll to the target); reactions (React in the action row and context menu, six quick emoji and More… for the system emoji picker, chips on the bubble); unread badges and read marks synced; attachments, paste and camera; share extension and notification service extension (iOS); two conversations side by side (`Pair.swift`); read-only Automations with "Edit in Chat"; Settings (tabs General, Devices, Host and Updates on the Mac, each sized to its content; one list on iPhone and iPad) with paired devices; Add a Device shows when the new device has paired; App Shortcuts; interface in English, Japanese, Simplified and Traditional Chinese, Korean, Spanish, French, German and Brazilian Portuguese (the last seven machine-translated); offline demo (`YOROZU-DEMO` in the pairing field, or `--demo`).
- **Mac app**: Developer ID signed, notarized DMG with Sparkle updates (stable and beta feeds), bundled plugin copy.
- **Zoom** (Mac and iPad, `Zoom.swift`): View > Zoom In (⌘+, ⌘=), Zoom Out (⌘−), Actual Size (⌘0) scale the app's text in seven steps from 75% to 200%, stored per device. The iPad shifts the system Dynamic Type size; the Mac, which has no Dynamic Type, scales text-style fonts and its AppKit text views. Window titles, toolbars, menus and pop-up buttons keep the system size on the Mac. The iPhone follows the system text size only.
- **Voice input** (opt-in, iPhone, iPad and Mac; `VoiceModel.swift`, `VoiceRecorder.swift`, `VoiceInput.swift`, `Transcriber.swift`): Settings › Voice Input turns it on and downloads LFM3-Audio-2B (Q4_K_M model and Q8_0 audio projector, 1.44 GB): iPhone and iPad (iOS 26 or later, greyed below) get the on-demand Apple-hosted asset pack `VoiceModel` through the `YorozuAssets` downloader extension ([release.md](release.md#voice-model-asset-pack)); the Mac gets the pinned Hugging Face revision, checked by SHA-256, into Application Support, excluded from backup, resuming a partial download; Delete Model removes it; language Automatic or one of the model’s 18 speech languages, named in themselves; the download waits for Wi-Fi (no cellular, hotspot or Low Data Mode) unless Download Using Cellular… is confirmed; the license notice links the LFM Open License v1.0. Devices under about 6 GB of RAM see the switch greyed. The composer's mic (left of Send) records 16 kHz mono up to 5 minutes with a waveform and timer: ✕ (Esc) cancels, ✓ (Return) inserts the transcript at the caret, send (⌘Return) posts draft and transcript as one message. Transcription runs on device through llama.cpp b11954 (`packages/Llama`, binary target pinned by checksum), off the main thread; a failure keeps the clip for Retry. Measured on an M4 Mac mini: 27 s of English speech in about 2 s, model load 0.2–5 s (cold), peak footprint about 0.8 GB with 1.9 GB resident including the mapped weights.
- **iPhone and iPad updates**: once a day the App Store build looks up its newest App Store version; a newer one shows a dismissible row at the top of the chat list that opens the App Store. Not on TestFlight or in demo mode.
- **Website** (`apps/web`): Astro site with pairing link page, AASA, and Mac download and update-feed redirects.
- **CI**: PR compile checks and relay tests; Mac beta per merge, promotion to stable on a `version.txt` bump; TestFlight upload per merge; web and relay deploy per merge ([release.md](release.md#ci)).

## Known limits

- Replies are whole messages, chunked by length; no streaming (`disableBlockStreaming`).
- The plugin sends only to devices with a live session; offline devices backfill from history on reconnect. A reply whose delivered text differs from its transcript text shows the transcript text in history.
- A Gateway restart drops live device sessions (devices re-handshake) and forgets pairing secrets not yet used.
- At most 16 paired devices (`MAX_DEVICES`, plugin and relay); adding one past that removes the oldest.
- An interrupted attachment upload starts over (partials are dropped after 30 minutes).
- `openclaw cron add --thread-id` accepts only numeric (Telegram) ids, so a job delivering into a Yorozu conversation is made with the agent's cron tool or `cron.add`.
- The plugin's keyed state (allowlist, read cursors) and OpenClaw's transcripts are not encrypted at rest beyond the disk's encryption.
- Relay only for now: the direct path (LAN, Tailscale, loopback) is decided for 0.10.0 ([#532](https://github.com/izyuumi/yorozu/issues/532)).
- No push on the Mac; no mute; no voice notes.
- Voice input: llama.cpp's xcframework has no iOS Simulator slice, so simulator builds leave voice input out (`TUIST_VOICE_INPUT=0`, [release.md](release.md#compile-checks)). The Mac model download runs while the app is open. On iPhone and iPad the system downloads the asset pack; the app waits for Wi-Fi before asking for it, but the system decides the network once the download runs.
