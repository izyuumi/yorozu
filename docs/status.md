# Status

Current state of `main`. Version: SemVer from the Conventional Commits since the last stable tag (`scripts/version.sh`). Product decisions: [OWNER_DECISIONS.md](../OWNER_DECISIONS.md). Release flow: [release.md](release.md).

## Implemented

- **Plugin** (`plugins/openclaw-yorozu`): host keys in the OpenClaw credentials store; relay connection with reconnect; Noise IK handshakes from allowlisted devices; `openclaw yorozu pair`, `devices`, `devices remove`. Text in and out through one OpenClaw thread session per conversation, with `run_started`, typing, `tool` rows and chunked whole replies; cron delivery into a conversation; history from the Gateway transcripts (`conv_list`, `history`); titles, rename, archive, delete; read cursors; attachments both ways (default limit 128 MB; `channels.yorozu.mediaMaxMb`, else `agents.defaults.mediaMaxMb`); replies both ways (reply targets into the turn, `[[reply_to…]]` out); reactions both ways (system events in, the message tool's `react` out); one sealed push per finished reply; read-only cron list; device list and settings; `pair_invite` for adding a Mac.
- **Wire** (`packages/YorozuWire`, plugin `src/wire.ts`/`src/envelope.ts`): [contract](ios-relay-contract.md); the plugin accepts both frame formats.
- **Relay** (`apps/relay`): Cloudflare Worker, one Durable Object per room, one-time pairing mailboxes, APNs sender, connect rate limit; deploys on merge after its tests.
- **Client** (`apps/ios`, one target for iPhone, iPad and native SwiftUI Mac): pairing by QR scan or pasted link with fingerprint check; a new Mac shows a code that a paired iPhone or iPad scans; conversation list, chat, outbox and cache; replies (Reply in the action row and context menu, quote headers that scroll to the target); reactions (React in the action row and context menu, six quick emoji and More… for the system emoji picker, chips on the bubble); unread badges and read marks synced; attachments, paste and camera; share extension and notification service extension (iOS); two conversations side by side (`Pair.swift`); read-only Automations with "Edit in Chat"; Settings (tabs General, Devices, Host and About on the Mac, each sized to its content; one list on iPhone and iPad) with paired devices; About with version, links, Sparkle update settings on the Mac, and Copy Diagnostics (`Diagnostics.swift`: app, device, connection state and this launch’s log, no keys or messages); Add a Device shows when the new device has paired; App Shortcuts; interface in English, Japanese, Simplified and Traditional Chinese, Korean, Spanish, French, German and Brazilian Portuguese (the last seven machine-translated); offline demo (`YOROZU-DEMO` in the pairing field, or `--demo`).
- **Mac app**: Developer ID signed, notarized DMG with Sparkle updates (stable and beta feeds), bundled plugin copy.
- **Zoom** (Mac and iPad, `Zoom.swift`): View > Zoom In (⌘+, ⌘=), Zoom Out (⌘−), Actual Size (⌘0) scale the app's text in seven steps from 75% to 200%, stored per device. The iPad shifts the system Dynamic Type size; the Mac, which has no Dynamic Type, scales text-style fonts and its AppKit text views. Window titles, toolbars, menus and pop-up buttons keep the system size on the Mac. The iPhone follows the system text size only.
- **Voice input** (opt-in, iPhone, iPad and Mac; `VoiceSetup.swift`, `VoiceModel.swift`, `VoiceSettings.swift`, `VoiceRecorder.swift`, `VoiceInput.swift`, `Transcriber.swift`, `packages/YorozuVoice`): Settings › Voice Input turns it on; Model picks the engine behind one protocol (`SpeechEngine`), each row with download size, languages, memory needed, streaming and license, a reason when the device can't run it, and Delete for a downloaded model that isn't selected; Licenses links [docs/voice-licenses](voice-licenses/README.md). Engines: Apple Speech (`SpeechAnalyzer`, iOS 26 and macOS 26 or later; the system installs each language, with progress; Automatic is the device's language and the list holds only the languages it supports there), LFM3-Audio-2B (Q4_K_M model and Q8_0 audio projector, 1.44 GB, 18 languages, through llama.cpp b11954 in `packages/Llama`), Whisper Large v3 Turbo (740 MB) and Whisper Small (489 MB), 99 languages, through WhisperKit (argmax-oss-swift 1.1.1), and Nemotron 3.5 ASR Streaming 0.6B (615 MB, 8 languages, Apple silicon) through FluidAudio 0.18.0. Until the owner picks, Apple Speech is the default where it runs, and a device that had downloaded LFM3-Audio-2B stays on it. Every downloaded model's files are pinned by Hugging Face revision and SHA-256 (`VoiceCatalog.swift`): iPhone and iPad (iOS 26 or later) get one on-demand Apple-hosted asset pack per model (`VoiceModel`, `VoiceWhisperTurbo`, `VoiceWhisperSmall`, `VoiceNemotron`) through the `YorozuAssets` downloader extension ([release.md](release.md#voice-model-asset-packs)), and a model whose pack App Store Connect doesn't have yet shows Not available yet; the Mac downloads into Application Support, excluded from backup, resuming a partial download. The download waits for Wi-Fi (no cellular, hotspot or Low Data Mode) unless Download Using Cellular… is confirmed. Dictionary (Settings › Voice Input › Dictionary, up to 200 words of 64 characters, stored on the device only and kept out of logs and Copy Diagnostics): each word goes to the engine as a hint (Apple's contextual strings, Whisper's prompt, Nemotron's custom vocabulary, an instruction to LFM3-Audio; a hinted LFM3-Audio transcript that repeats a word or phrase three times in a row, is mostly dictionary words or reads back the Vocabulary list is decoded again without hints, and when that one loops too nothing was recognized, `TranscriptDegeneration.swift`; each LFM3-Audio decode stops after 33 tokens a second of audio, at least 128 (three times the fastest speech measured, 10.4 tokens a second), and one that gets there counts as a loop, `TranscriptBudget.swift`), and a word with Heard As replaces that text in every engine's transcript, longest match first, whole words in spaced scripts, ignoring case and width (`VoiceDictionary.swift`, tested with `swift test --package-path packages/YorozuVoice`). The composer's mic (left of Send) records 16 kHz mono up to 10 minutes (`RecordingLimits.maxSeconds`; then "Recording stopped at the 10-minute limit.") with a waveform and timer: ✕ (Esc) cancels, ✓ (Return) inserts the transcript at the caret, send (⌘Return) posts draft and transcript as one message. The engine loads while the owner speaks and transcribes off the main thread; a failure keeps the clip for Retry. Background (iPhone and iPad, the `audio` background mode): recording keeps going when the owner switches apps or locks the phone, with the system's mic indicator; `Dictation.swift` owns one session per conversation, so the composer, the Talk to Yorozu control and the Live Activity drive the same recording. A call or Siri pauses it (Paused, the samples kept) and it resumes when the system says so, else with Resume; losing the input route (AirPods removed) or an engine configuration change restarts the tap on the new input, same clip (`RecordingMachine.swift`, tested). Each clip streams to `VoiceClips/` as it is spoken (`ClipStore.swift`, tested) and stays until its text is in the composer; a clip a killed app left is transcribed into its conversation's composer the next time the app is in front, never sent. Live Activity: a Recording row with Cancel and Stop (`StopRecordingIntent`, `CancelRecordingIntent`; Stop transcribes into the composer, never sends), then Transcribing, then Done (in the background with the Transcript Ready or Recording Stopped alert, plus a local notification that opens the conversation) or Failed. After a stop, per engine (`VoiceEngineID.usesGPU`, `TranscriptionPlan.swift`, tested): Apple Speech (the system's speech service) and Nemotron (Core ML on CPU and Neural Engine) transcribe at once, in the background too, under a background task; Whisper (its mel spectrogram on `.cpuAndGPU`) and LFM3-Audio-2B (llama.cpp on Metal) need the GPU, which iOS denies in the background, so stopped in front on iOS 26 with `BGTaskScheduler.supportedResources` containing `.gpu` they run in a continued-processing task (`to.yumi.yorozu.ios.voice-transcribe.<uuid>`, system progress UI, expiry keeps the clip), stopped in front otherwise they run in front, and stopped in the background (Lock Screen Stop, the 10-minute limit) or failing there they wait and transcribe when the app comes forward. Measured on an M4 Mac mini with six synthetic English and six synthetic Japanese clips (two system voices each; word error rate for English, 64 words, character error rate for Japanese, 146 characters; raw, then with a dictionary of hints and Heard As fixes): LFM3-Audio-2B English 10.9%, 0.0% with the dictionary, Japanese right on one voice and looping or empty on the other (52% with the dictionary; with the retry, six regenerated Japanese clips gave 12.2% and 9.8% with the dictionary and no loop, and slowed, noise-only, silent or humming audio, where hinted LFM3-Audio read the dictionary back, gave a short phrase or nothing; 8 s of silence that looped to the end of the context took 132 s, and 5.4 s with the token budget); Whisper Large v3 Turbo English 10.9%, 1.6%, Japanese 4.1%, 0.0%, about 0.5 s a clip after a 121 s first load (Core ML compiles once); Whisper Small English 10.9%, 1.6%, Japanese 24.7%, 15.1%; Nemotron 3.5 ASR English 10.9%, 3.1%, Japanese 17.1%, 17.1%, about 0.1 s a clip; Apple Speech English 10.9%, 4.7%, Japanese 4.1%, 1.4% (its contextual strings changed nothing). LFM3-Audio-2B alone: 27 s of English speech in about 2 s, model load 0.2–5 s (cold), peak footprint about 0.8 GB with 1.9 GB resident including the mapped weights.
- **Widgets, controls and Live Activity** (iPhone and iPad, iOS 18 or later; `YorozuWidgets` extension, `Sources/WidgetShared`, `WidgetPublisher.swift`, `YorozuActivities.swift`): the app and the notification service write a snapshot to the App Group (`WidgetSnapshot.json`: up to 12 conversations with title, pinned, unread count and last reply time, the total unread count as on the badge, the accent, and the latest reply's first line only while Settings › Show Message Previews in Widgets is on, off by default), atomically, only when it changed, then reload the widgets; demo mode writes none (its taps open only new conversations, Ask and Talk) and unpairing deletes it. Conversations widget (small, medium, large; medium and large chosen per widget from the snapshot) with pinned then recent rows, unread dots, relative times, a tap opening the conversation, + (new conversation) and Ask (new conversation, keyboard up). Lock Screen accessories: circular (unread count or glyph), rectangular (latest conversation and count), inline ("2 new replies, latest: Trip planning"). Lock Screen launcher (circular, no snapshot read): Ask, the Yorozu mark alone (new conversation, keyboard up). Control Center: New Conversation and Talk to Yorozu (new conversation with voice input, or the voice setup when the model isn't ready). Titles and previews are privacy-sensitive (hidden on a locked screen); counts stay. Live Activity (Settings › Show Live Activity, on by default, the same `turnLiveActivity` key as before): one device-local activity for the whole app (`YorozuActivityAttributes`), whose state is a list of at most 8 jobs (turn, recording, transcribing, needs you; running, done or failed; a tool step count and times), each keyed by a random token and never by a conversation. What a token is about (the conversation to open, and its title only while widget previews are on) is in `ActivityLabels.json` beside the widget snapshot, written by the app and the notification service and pruned to the live tokens; the views read it at render time and show a title only while previews are on, else "Working", "Recording", "Transcribing", "Needs you", "Done" or "Failed"; never message text, tool names or arguments. Lock Screen and expanded Dynamic Island: up to 3 rows (needs you, recording, running, finished; newest first) plus "+N more", each opening its conversation (a token without a label opens the app); compact: the mark, and "!" for needs you, else a pulsing mic while recording, else the running count; minimal: the mark with that badge. Turns from the in-app watcher start it when the app leaves the foreground (ActivityKit can't start one from the background); recording and transcription start it in the app and keep it on return, while returning otherwise ends it; a running recording row adds Cancel and Stop buttons, which act in the app without opening it. Finished rows linger 2 minutes; with nothing running and nobody left to clear them, it ends and the system dismisses it then; no jobs, no activity; a stale date marks 15 minutes without an update. The notification service updates it silently: a reply marks the turn done and drops its approval row, a failure marks it failed, an approval adds a needs-you row (it can't start an activity). It alerts only for events no push announces: a transcript ready, the recording limit, a send the relay refused. With a plugin listing `liveActivityPush` (its relay has an APNs key), the activity takes a push token and the app reports it, its jobs and each running turn's conversation over the encrypted session; the plugin then pushes counts-only states through the relay while the app is suspended (tool steps at most every 15 s at priority 5, a finished turn at once at priority 10, never an alert; `end` when nothing runs), passing recording and transcription rows through unchanged. The relay sees the push token, push times and that plaintext state of tokens, kinds, states, counts and times, nothing about conversations ([contract](ios-relay-contract.md#live-activity-push)). No push-to-start.
- **iPhone and iPad updates**: once a day the App Store build looks up its newest App Store version; a newer one shows a dismissible row at the top of the chat list that opens the App Store. Not on TestFlight or in demo mode.
- **Website** (`apps/web`): Astro site with pairing link page, AASA, and Mac download and update-feed redirects.
- **CI**: PR compile checks and relay tests; Mac beta per merge, promotion to stable by merging the release PR; TestFlight upload per merge; web and relay deploy per merge ([release.md](release.md#ci)).

## Known limits

- Replies are whole messages, chunked by length; no streaming (`disableBlockStreaming`).
- The plugin sends only to devices with a live session; offline devices backfill from history on reconnect. A reply whose delivered text differs from its transcript text shows the transcript text in history.
- A Gateway restart drops live device sessions (devices re-handshake) and forgets pairing secrets not yet used.
- At most 16 paired devices (`MAX_DEVICES`, plugin and relay); adding one past that removes the oldest.
- An interrupted attachment upload resumes from the chunks the plugin spooled to disk (dropped after 24 hours idle, at most 8), also across a plugin or Gateway restart and an app relaunch; against a plugin without `resume` it starts over. Downloads resume from the chunks the device kept.
- `openclaw cron add --thread-id` accepts only numeric (Telegram) ids, so a job delivering into a Yorozu conversation is made with the agent's cron tool or `cron.add`.
- The plugin's keyed state (allowlist, read cursors) and OpenClaw's transcripts are not encrypted at rest beyond the disk's encryption.
- Relay only for now: the direct path (LAN, Tailscale, loopback) is decided for 0.10.0 ([#532](https://github.com/izyuumi/yorozu/issues/532)).
- No push on the Mac; no mute; no voice notes.
- Widgets: the snapshot holds 12 conversations, so the widget's configuration offers only those; one chosen later drops out until it is among them again. A Live Activity starts only while the app is still in front (`.inactive`), so pulling down Control Center over the app with a turn running starts one, which ends on return. After a crash the snapshot can still say the app is in front, so the notification service leaves the counts alone until the app runs again.
- Voice input: llama.cpp's xcframework has no iOS Simulator slice, so simulator builds leave LFM3-Audio-2B out (`TUIST_VOICE_INPUT=0`, [release.md](release.md#compile-checks)); the other engines stay. The Mac model download runs while the app is open. On iPhone and iPad the system downloads the asset pack; the app waits for Wi-Fi before asking for it, but the system decides the network once the download runs.
- Voice input: Nemotron 3.5 ASR Streaming and Apple Speech have no live partial results; they get the clip whole and transcribe it after recording stops.
