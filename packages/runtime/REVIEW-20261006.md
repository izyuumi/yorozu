## Implemented changes

- One YOLO-exemption predicate covers secretary ownership, harness ownership, and
  harness thread kind at runner admission, new approval requests and pending-card
  mass approval. The production baseline has no Rust turn `packet.bypass`; its
  existing setting is sampled once per native attempt, rather than read again by
  the approval callback. No new bypass authority is introduced.
- Harness answers, person controls and person creation require an actual local
  connection or a paired compatible device with the corresponding capability.
  Missing provenance, channel-origin names, fabricated local IDs and old peers
  cannot invoke these callbacks.
- Host-selected native workspace is stored with the thread. Changing it clears
  the old native session; selecting the same workspace preserves that session.
  Person/harness sessions remain in their own ledgers and their preserved legacy
  metadata is not rewritten by this workspace hook. In the
  old assembled code `currentHome` was separately re-read before runner dispatch,
  so the review's unconditional-per-turn-session-reset claim was overstated.
  The real workspace/session consistency issue is now explicit and tested.
- Duplicate specialist dispatch returns before any preparation or admission side
  effects; it cannot create a second user event or a false not-started terminal.
- Background harness action/status emissions refresh the thread list.
- Broker actor-scope validation checks an authentic minted scope and unchanged
  identities/settings of its entire agent chain, not unrelated registry revision
  numbers. Memory/delegation APIs retain their existing revision fencing.
- Selecting/signing into a different account does not retire actors explicitly
  bound to the old account. Refresh and select are non-retirement reasons;
  invalidation, sign-out, replacement and close retain their safety behavior.
- UI navigation has a durable non-fencing receipt **before** opening the UI. It
  does not resolve the native action. A later explicit choice is still sent once.
  Native-answer loss continues to create an unknown hold. Existing old unknown
  receipts are not retrospectively cleared.
- Idle owners are no longer evicted from a live daemon. Listeners and leases stay
  attached. The owner limit is 64, with refusal at capacity instead of detaching
  a live listener. This is a bounded-resource limit, not unlimited-agent support.
- Failed startup promises are cleared, allowing a subsequent explicit turn on a
  healthy shared process to open its session. Unavailable processes, unsettled
  executions and unknown receipts remain fenced; this does not replay a turn.
- Only a positively `busy` + `not-submitted` peer receipt gets a one-second,
  per-recipient coalesced retry timer. Timers are cleared on shutdown. Unknown
  handoffs are never retried. The interval bounds retry rate; pending busy data
  can remain durable indefinitely.
- Production recipient admission requires declared catalog inbox capability
  before preparing/starting the recipient. Packaged Hermes declares its native
  inbox capability; connected OpenClaw does not. The injected runtime fixture
  seam can still omit this catalog hook to test negotiated capabilities directly.
- Peer-message identity is stable across sender epoch/session/work changes:
  `(agentId, nativeMessageId)` identifies custody; recipient/text/exchange
  conflicts are still rejected. Currency epochs continue protecting action
  answers. A previously delivered message is not delivered again.
- Packaged entry ignores ambient unconfined harness selection. Developer-only
  unbundled opt-in remains separate from the packaged factory.
- Account sign-in requires the helper manifest's `static-input-checks`
  provisioning marker. Missing, invalid or `absent` provisioning rejects before
  native/browser/account-service activation. Unprovisioned hosts do not expose
  the SIWC capability callbacks to the production transport. This necessary
  packaging check is not proof of native account readiness.
- Seatbelt policy removes ambient signals and permits only `(target self)`.
  Text-policy regression passes; actual kernel enforcement and native subprocess
  cancellation compatibility were **not** tested. This remains a native QA gate.
