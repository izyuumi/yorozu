Fixtures are raw Durable Object storage snapshots plus signing keys for relay storage and wire compatibility replay.
Produced by compat.test.ts capture on the source commit named by each fixture's producer field (v0.13.0 for the shipped baseline).
All keys are test-only, generated by the capture tests; never use them outside tests.

Capture tests are skipped unless `VITE_COMPAT_CAPTURE=1` and `VITE_COMPAT_PRODUCER` is set to the source commit SHA.
Run from `apps/relay`:

```sh
VITE_COMPAT_CAPTURE=1 VITE_COMPAT_PRODUCER=<git-sha> pnpm exec vitest run --project worker src/compat.test.ts -u
```

Capture writes snapshots to `compat-fixtures/captured/<scenario>.json` and also logs each fixture.
Copy captured files by hand to `compat-fixtures/<producer>-<scenario>.json` to include them in replay.
Replay loads only `compat-fixtures/*.json`, excluding `captured/`.

The `worker` project runs the current relay and replays every committed fixture:
v0.13.0 storage proves forward compatibility, and current storage also replays.
The `worker-v0.13.0` project runs the unmodified shipped source in
`compat/v0.13.0` (relative to `apps/relay`) and replays only producers that do
not start with `v0.13.0`, proving rollback from newer storage. Capture never runs
in that project. Neither replay project needs Git history or network access.

R1 checks nonce rejoin and saved alert/Live Activity push targets; R2 checks
revocation closes the socket and forgets both targets; R3 announces an initially
unannounced roster before nonce rejoin; R4 nonce-rejoins all sixteen saved devices.
These cases make no fresh token joins: the current relay's intentional refusal
of a seventeenth pending device (`4011`, token kept) is outside the shared proof.
